Kernel Borderlands

Behavioural detection and graded, gated containment for Linux servers, enforced inside the kernel. An eBPF sensor scores what processes do, BPF-LSM hooks enforce five containment levels behind authorisation gates, and every decision lands in a tamper-evident audit chain.

How it works

Transitions, not events

One execve() is not an attack. The same call after a privilege change, in an unexpected process tree, after a burst of writable-and-executable memory, very likely is. KB follows each process through behavioural states and acts at the border between normal and hostile.

Architecture

Five subsystems, Unix sockets only

Telemetry and control travel on separate root-owned sockets under /run/kb/, so a burst of events can never delay a containment order. The only TCP listeners are bound to loopback, apart from the operator's SSH port.

C · eBPF · Ring 0

kb-core

One CO-RE object with tracepoints, kprobes, TLS-write uprobes and five BPF-LSM enforcement hooks, writing to a single ring buffer (a perf-buffer build exists for kernels older than 5.8). A per-process token bucket keyed on thread group, start time and resource limits telemetry floods; the sensor drops its own syscall samples in-kernel.

Go

kb-control-plane (kbd)

In-memory L1 state backed by SQLite in WAL mode, per-process YAML policy, the SHA-256 audit chain, an entropy and CUSUM beacon detector, 13 gRPC calls and an HTTP/SSE API for the dashboard. All enforcement is authorised here; an observe-only mode records what it would have done.

Python · Ray

kb-aads

A live, advisory pipeline: an ingest agent feeds Patrollers, Hunters ask for a level, a Judge runs a Jury quorum, and an Executor stages CGROUP to TERMINATE through kbd. Learned policies are gated behind a versioned feature schema and are off by default until retrained.

Rust

kb-checker

A stateless watchdog that hashes the loaded BPF programs, checks sensor liveness and the containment map, and can fall back to a host lockdown. In release 1.1 it is installed but kept down while its recovery path is repaired.

Go · Rust · TypeScript

kb-op

kbctl drives the stack over gRPC; kb-tui (Rust, ratatui) is reached through a dedicated sshd on port 2222; the React 19 dashboard is served on 127.0.0.1:8082; kb-mcp offers one read-only statistics tool over the Model Context Protocol.

Packaging

Install and services

An Ubuntu .deb and an Arch package from one install target. Nothing starts on install; kbctl up starts kbd, the sensor, the dashboard and the SSH console.

Detection

Scores, evidence and rules

Zones and states

Every process is SAFE, SUSPICIOUS or BORDERLANDS, and the behaviour engine moves it through SAFE, OBSERVED, SUSPICIOUS, BORDERLANDS and COMPROMISED as evidence accumulates.

Evidence and rules

Evidence flags (privilege change, credential-file reads, RWX memory, cross-process writes, shells without a terminal, exec from /tmp or memory, connect bursts, ptrace) feed 19 shipped behaviour rules, all of which can now fire.

Features for learning

Schema v6: the six dimension scores, process-tree file and network evidence, destination class and a known-destination allowlist, per-process counters, and an opt-in bytes-sent counter. Labels are never inputs.

Containment

Five levels behind two gates

LevelNameEffectReversible
0NONEObserved only–
1CGROUPResource throttle (cgroup v2)Yes
2SECCOMPDenies exec, network connect and bind, and sensitive filesYes
3NAMESPACEAlso denies all file opens and adding executable memoryYes
4TERMINATEAll of the above, then SIGKILL through a pinned pidfdNo

Authorisation gates

The Critical Process Module refuses PID 1, kernel threads, protected PIDs and protected executables, including KB itself. Critical Workload Protection then refuses registered workloads by path or SHA-256 hash. Both run before the containment map is written, and releasing containment is never gated.

A kill that must be confirmed

kbd applies its own copy of the gates, pins the target with pidfd_open, sends level 4 and waits up to 3 s for the sensor's acknowledgement on kbct.sock. It kills only on applied; a refusal or silence means no kill.

Attack lab: rules and baselines

Test split of four pooled lab captures (72 attack and 80 benign executions); every fit and threshold chosen on the training split only, test split opened once. Benign runs include deliberate lookalikes such as sudo tar backups and credential audits.

What holds up

  • BORDERLANDS raised no benign alarms on the test split.
  • Process injection and the memory exploit reach BORDERLANDS 5 of 5.
  • Detection is fast: a median of 3 ms from the first malicious action to the zone change in run 20261101T225841.

What does not yet

  • SUSPICIOUS flags about half of the benign lookalikes.
  • The scripted C2 beacon is never detected, and no current feature separates it from a benign heartbeat.
  • Tree evidence, byte counts and destination identity did not improve separation.

Real exploits

Re-runs of the LID-DS 2021 scenarios (real vulnerable services, normal traffic and exploits) are being prepared: 13 of 15 scenarios build in the lab, and captures are next. A separate archive project, KB-LVA, tracks provenance for Linux reproduction artifacts; none is lab-validated yet.

Get started

Install and run

Requirements

  • x86_64, Linux 5.10 or newer with BTF (/sys/kernel/btf/vmlinux) for the full feature set
  • CONFIG_BPF_LSM=y and bpf in the active LSM list for enforcement; without it the sensor runs telemetry-only
  • Ubuntu 22.04 / 24.04 or Arch Linux (tested); other distributions in the docs

Check a host

ls /sys/kernel/btf/vmlinux
cat /sys/kernel/security/lsm      # "bpf" listed?
# packages are published as GitHub Release assets
sudo apt install ./kernel-borderlands_*.deb             # Ubuntu / Debian
sudo pacman -U kernel-borderlands-*.pkg.tar.zst          # Arch Linux

sudo kbctl up              # starts kbd, the sensor, the dashboard and the SSH console
kbctl dashboard open       # or: kbctl ssh connect
kbctl audit verify

Field manuals for Ubuntu and Arch Linux, and releases. Building from source: packaging/README.md.
