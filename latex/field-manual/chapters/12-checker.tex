\chapter{kb-checker: Under Maintenance and Repairs}
\label{ch:checker}
\begin{kbwarn}[STATUS: DOWN, BY DECISION]
\cmd{kb-checker} is \textbf{under maintenance and repairs} and is kept down. This is deliberate and
enforced in three places, so that no one starts it by accident.
\end{kbwarn}

\section{How it is kept dead, and how you start it}
Nothing starts \cmd{kb-checker} automatically. A manual start is deliberately \emph{allowed}.
\begin{center}\small
\begin{tabularx}{\textwidth}{@{}L{4.6cm}Y@{}}
\toprule
\textbf{Mechanism} & \textbf{Effect}\\
\midrule
The package never enables it & No \texttt{systemctl enable} for \unit{kb-checker.service} anywhere in the packaging.\\
\file{/usr/lib/kb/migrate-legacy.sh} & On every install and upgrade it runs \texttt{systemctl disable kb-checker}, so a checker enabled by an older dev install no longer starts at boot. On a \emph{fresh install} it also stops it; on an \emph{upgrade} a running checker is left alone, so a manual start survives upgrades.\\
\cmd{kbctl up} & Starts \texttt{kbd}, \texttt{kb-sensor}, \texttt{kbopd}, \texttt{sshd@kb-operator} only.\\
\cmd{kbctl status} & Prints \texttt{UNDER MAINTENANCE AND REPAIRS (kept down)}; if you have started it by hand, \texttt{active, STARTED MANUALLY (under maintenance and repairs)}.\\
\unit{kbagents.service} & No longer \texttt{Requires=} the checker, which would have started it.\\
\bottomrule
\end{tabularx}
\end{center}
\begin{lstlisting}[style=console]
$ systemctl is-enabled kb-checker      # disabled: no boot autostart
$ sudo systemctl start kb-checker      # your decision; it now runs
$ kbctl status | tail -1
kb-checker.service           active, STARTED MANUALLY (under maintenance and repairs)
$ sudo systemctl stop kb-checker       # back to dead
\end{lstlisting}

\section{What you lose while it is down}
\cmd{kb-checker} audits eBPF bytecode and map integrity, sensor liveness, the \cmd{kbd} gRPC health, and the swarm.
It also runs the \emph{Tampering Containment Protocol}: on a confirmed integrity violation it stops the sensor,
detaches the eBPF links and quarantines the host's network. With it down:
\begin{itemize}
\item \textbf{No automatic tamper response.} Nothing independently notices if the sensor or its programs are altered. Treat the host as \emph{observed but not self-defending}.
\item \textbf{No false lockdowns either.} The checker's fail-closed behaviour can isolate a host over a missing dependency (for example, an absent swarm). Its absence removes that risk during demos.
\item \texttt{/api/services} in the dashboard will report the checker as down. That is expected, not a fault.
\end{itemize}

\begin{kbwarn}[A MANUAL START ARMS A COMPONENT THAT CAN LOCK DOWN THE HOST]
Starting it by hand can stop the sensor and firewall the host. Do it only on a machine you can reach
out-of-band. Never \texttt{systemctl enable} it as a workaround; the next package install or upgrade removes
that autostart again. Once the repairs are signed off, delete the \texttt{kb-checker.service} line from
\texttt{maintenanceUnits} in \file{kb-op/kbctl/svc.go}, add the unit to \texttt{stackUnits}, drop the
\texttt{systemctl disable kb-checker} step from \file{packaging/scripts/migrate-legacy.sh}, and rebuild.
\end{kbwarn}

\section{Design invariants that still apply}
The watchdog is intentionally \textbf{stateless} and opens \textbf{no network listener} (it serves diagnostics only
on the local socket \file{/run/kb/kbc.sock}). When repairs resume, do not add persistent state or a network
listener to it: that is a security design invariant of the project, not a style choice.
