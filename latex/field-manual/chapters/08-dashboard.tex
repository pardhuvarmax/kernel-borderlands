The dashboard's JavaScript builds its API address as \texttt{http://<the host you loaded it from>:8080}.
Loaded via \texttt{127.0.0.1} it calls \texttt{127.0.0.1:8080}; loaded via \texttt{localhost} it calls
\texttt{localhost:8080}. Both origins are in the packaged allowlist; any other hostname is blocked by the
browser until you add it.

\section{Commands}
\begin{lstlisting}[style=console]
$ kbctl dashboard up        # enable + start kbopd, wait for the port, print the URL
dashboard up: http://127.0.0.1:8082
$ kbctl dashboard open      # up (if needed) + launch the default browser
opened http://127.0.0.1:8082
$ kbctl dashboard status    # exit 0 if active AND listening, 3 otherwise
kbopd.service: active, http://127.0.0.1:8082 listening=true
$ kbctl dashboard url       # just print it, handy in scripts
$ kbctl dashboard down      # stop + disable
\end{lstlisting}
\cmd{up} polls the port for up to 15~seconds. If no browser can be launched (a headless server),
\cmd{open} prints the URL and succeeds; open it from another machine through the tunnel below.

\section{Reaching it from your workstation}
The dashboard binds loopback only. The operator \cmd{sshd} deliberately forbids TCP forwarding
(\texttt{AllowTcpForwarding no}), so tunnel through your \emph{normal} SSH service (port 22):
\begin{lstlisting}[style=console]
workstation$ ssh -N -L 8082:127.0.0.1:8082 -L 8080:127.0.0.1:8080 you@kb-host
workstation$ xdg-open http://127.0.0.1:8082
\end{lstlisting}
Forward \emph{both} ports: the page comes from 8082, the data from 8080. Use \texttt{127.0.0.1} (or
\texttt{localhost}) in the browser, matching the CORS allowlist.

\section{The API token: how the action buttons are authorized}\label{sec:token}
The three mutating routes are wrapped in \texttt{requireAPIToken} and \textbf{fail closed}: without a configured
token they are unusable, and with one they need a matching \texttt{Authorization: Bearer} header. The package
sets this up so the buttons work without weakening that check:
\begin{enumerate}
\item \textbf{Generation.} On install, \file{/usr/lib/kb/migrate-legacy.sh} creates \file{/etc/kb/api.env} containing \texttt{KB\_HTTP\_API\_TOKEN=}\emph{64 random hex characters} (mode 0640, \texttt{root:kb}). It is created once and never overwritten.
\item \textbf{Server.} \unit{kbd.service} loads it with \texttt{EnvironmentFile=-/etc/kb/api.env}. \cmd{kbd} must be \emph{restarted} to read a newly created token; the installer prints a notice and does not restart \cmd{kbd} for you.
\item \textbf{Browser.} \cmd{kbctl dashboard open} opens \texttt{http://127.0.0.1:8082/\#token=...}. A URL \emph{fragment} is never sent to any server. The page moves it into \texttt{sessionStorage} (this tab only, cleared when the tab closes) and removes it from the address bar. It is \emph{not} compiled into the dashboard bundle, so loading the page without the fragment gives read-only views.
\end{enumerate}
\begin{lstlisting}[style=console]
$ kbctl dashboard open              # token handed to the browser automatically
$ kbctl dashboard url --token       # print the tokened URL for another browser; treat as a secret
$ sudo cat /etc/kb/api.env          # the token itself (root or the kb group)
\end{lstlisting}
\begin{kbwarn}[LIMITS OF THIS DESIGN]
Anyone who can read \file{/etc/kb/api.env} (root and the \texttt{kb} group, which includes \texttt{operator}) can
isolate processes through the HTTP API; so can anyone who sees the tokened URL (it appears in the process list
of the machine while the browser launches). The API listens on loopback only. To rotate the token, delete
\file{/etc/kb/api.env}, run \texttt{sudo /usr/lib/kb/migrate-legacy.sh upgrade}, then \texttt{sudo systemctl restart kbd}
and reopen the dashboard. If the buttons report ``API token missing or wrong'', you opened the page without
the fragment (use \cmd{kbctl dashboard open}) or \cmd{kbd} has not been restarted since the token was created.
\end{kbwarn}
\begin{kbnote}[VERIFICATION STATUS]
The dashboard compiles with the new logic, the served bundle contains it, the fragment parsing was tested, and
\cmd{kbctl dashboard url --token} was tested against a token file. It was \textbf{not} exercised in a real
browser against a live \cmd{kbd} (no browser extension and no root in the build sessions); step D of the acceptance
checklist closes that.
\end{kbnote}
